J9 · Trade cycles — multi-hop swaps
DEMO

A trade cycle chains gives-and-wants across several participants so everyone both gives and receives. The law of this surface: every leg needs its own consent from the giving participant — a refusal, a dropout or an expired consent window stops or re-plans the whole cycle. Other legs are never silently committed: a stop is a stop.

What is real here, and what is not

Real (kernel-driven): Execution. Per-leg consent, refusal, withdrawal, window expiry and the atomic commit run through the commerce kernel's TradeCycle execution aggregate, imported from @unicom/commerce: every state and chip below is kernel truth.

Demo-only: The candidate cycles and the participant identities. Discovery (bounded search over the offer graph) remains the agent lane's, which the web host cannot import — candidates arrive as committed demo fixtures and are validated by the kernel's cycle-shape laws when they open.

Wired (new this phase): Executed by the commerce kernel. Each consent travels as an AUTHORIZE_TRADE_CYCLE_LEG command carrying its per-leg authorization reference; with every leg authorized, EXECUTE_TRADE_CYCLE commits all legs atomically — all or none. Attribution by anyone other than the giver holds the leg UNKNOWN, never fails it.
