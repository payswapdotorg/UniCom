# W2-004 — Trust, Proof & Security Immune System + Opportunity Graph

Lane: Worker 2
Status: COMPLETE
Dependencies: W2-003 (merged @ 5f3fbe9)

## Objective
Build the trust and security layer over the W2-003 lab: UserTrust/AgentTrust/CapabilityTrust semantics, TransactionProof records, the Security Immune System (Signal/ThreatSignature/defensive broadcasts), and the opportunity graph that connects commerce intents to lab-promoted opportunities — with adversarial evidence against the five fraud archetypes.

## Scope
Under `packages/agent` (module-system conforming; zcode-cli kernel integration where the plane requires it), on top of W2-003's Opportunity Lab + actor-as-capability + promotion gates: trust semantics — UserTrust, AgentTrust, CapabilityTrust as journaled/derived records with explicit evidence chains (never ambient scores); TransactionProof — verifiable records binding a commerce transaction to the evidence that justifies its trust outcomes (inspection of proof must be possible WITHOUT trusting the asserting party); the Security Immune System — SecuritySignal ingestion, ThreatSignature classification, defensive security broadcasts to affected principals (capability-scoped, minimum-necessary disclosure per the W2-003 privacy contract), quarantine/suspension as reversible capability attenuation (never deletion); the opportunity graph — typed edges from Buyer CommerceIntent through lab formations to merchant-visible opportunities, queryable with provenance (every edge explains its promotion evidence); adversarial evaluation suites for the five fraud archetypes (fake review/review ring, wrong-item shipment, false buyer claim, false non-delivery, return/refund abuse) — each archetyped as adversarial evidence flows the immune system must catch, and each with an evasion attempt the system must still catch (defense must not rely on attacker cooperation); promotion gates for every new runtime-reachable security action (same append-only hash-chained gate discipline as W2-003).

## Truth distinctions
Trust is earned evidence, never an ambient number; a proof must verify against its evidence chain, not its asserter; quarantine/suspension attenuates capabilities reversibly — the actor's ledger history is append-only; broadcast disclosure follows the coordination-privacy contract (no raw cross-principal intent leakage through security channels); immune-system actions are lab-gated (un-promoted detection logic is unreachable from the runtime plane).

## Acceptance scenarios
1. Trust records: UserTrust/AgentTrust/CapabilityTrust derive only from journaled evidence chains; removing the evidence invalidates the derived trust (asserted, not conventional).
2. TransactionProof: a proof verifies against its evidence chain without the asserter's cooperation; a tampered evidence chain fails verification deterministically.
3. Review ring: a coordinated fake-review ring (colluding principals, timing correlation, duplicate content signals) is detected and quarantined; the quarantine is reversible and the principals' ledgers remain append-only.
4. Wrong-item shipment + false non-delivery: both archetypes are distinguished from honest disagreement via evidence (carrier observation vs buyer claim vs merchant attestation) — the immune system's classification preserves tri-state where evidence is UNKNOWN.
5. False buyer claim + return/refund abuse: adversarial claims that contradict journaled commerce facts (from the opaque commerce seam) are flagged; honest claims are NOT flagged (precision asserted, not just recall).
6. Evasion resistance: for each archetype, an evasion variant (e.g. ring members mixing honest activity, staggered timing, partial truths) is still caught OR the failure is explicitly journaled as a known limitation — silent evasion is a bug.
7. Broadcast discipline: a defensive broadcast reaches exactly the affected capability-scoped principals; an adversarial observer of the broadcast channel reconstructs no more intent information than the coordination contract explicitly discloses (cross-principal inference blocked).
8. Opportunity graph provenance: every graph edge from intent to merchant-visible opportunity carries its promotion evidence reference; a graph query without provenance is rejected by contract.
9. Determinism: identical evidence + intent inputs produce identical trust/classification/graph outputs on replay.

## Constraints
Commerce facts enter ONLY through the opaque commerce seam (typed versioned query interface from W1-003 — no direct kernel/event access, no opportunity semantics on the commerce side); no UI/connector concerns (Worker 3 lane); no provider integrations; immune actions lab-gated; no ambient authority; no production mocks; adversarial suites must be REAL tests; no scope beyond the agent/trust/lab lane.
