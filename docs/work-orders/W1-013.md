# W1-013 — Canonical Vite Production-Build Evidence

**Phase:** Product Completion & Build Readiness, issue #12  
**Owner:** Worker 1  
**Status:** READY_FOR_TL_DISPATCH  
**Lane:** Build/release evidence only  
**Write surface:** `.github/workflows/**` only if a safe, non-deploying build workflow is necessary; `docs/product-completion/build/**`; no application source by default.

## Objective

Prove the canonical Vite production build using the repository's unchanged canonical configuration in an environment with at least 3 GB free memory. The historical `--sourcemap false` build is useful variant evidence but is **not** proof that the canonical hidden-sourcemap build passes.

## Required steps

1. Verify the current default-branch head, package manager/lockfile, Node version, Vite config, build scripts, source-map policy, and available CI workflows before changing anything.
2. Run the canonical build in a clean environment. Record the actual available-memory floor during the build (not just total machine RAM), OS/runner image, Node/package-manager versions, exact command, commit SHA, start/end UTC timestamps, exit code, elapsed time, warnings and any failure output.
3. Use an existing suitable runner if possible. If a workflow is needed, create a **build-only** workflow (manual and/or pull-request trigger) that cannot deploy, publish, mutate production or use deployment credentials. Do not introduce paid infrastructure.
4. Capture canonical output file count, total size, stable SHA-256 manifest or digest summary, and evidence location. Do not commit a huge generated `dist` directory solely to prove a build; retain small reviewable logs/manifests and the CI run link when available.
5. If the canonical build fails, classify the exact cause and preserve logs. Do not change source-map behavior, lower verification standards, or relabel the no-sourcemap variant as canonical success merely to make the gate green.
6. Independently rerun the final command on the final merged commit.

## Acceptance

- [ ] The canonical, unchanged build command has a measured free-memory floor of at least 3 GB and exits 0 on the candidate merged commit; or the exact blocker, complete failure evidence and bounded remediation proposal are preserved, and the TL explicitly marks this gate BLOCKED rather than PASS.
- [ ] Evidence includes commit, command, environment/runtime versions, memory floor, duration, exit status, output summary and hashes.
- [ ] Any workflow is build-only, uses no deployment secrets and has no publish/deploy steps.
- [ ] No sourcemap-policy or production configuration was silently weakened.
- [ ] TL independently reproduces and signs off the record.

## Forbidden

Production deploy; production mutation; provider/API credentials; changing the canonical build policy without operator approval; treating the prior no-sourcemap variant as the canonical build; hiding environmental failures.
