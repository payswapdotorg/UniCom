## Objective

Make UNiCOM's AI-native value legible in the interface: one Main Agent operating toward the user's goal, bounded organization/capability use where supported, visible plans and decisions, simulation before consequential action, and separate trust/proof/security explanations. The surface should express the existing Goal → Observe → Plan → Simulate → Approve → Execute → Verify → Learn loop without inventing runtime capabilities that are not wired.

## Required behavior

1. Make the Main Agent's objective, current step, relevant evidence, uncertainty and next action understandable. Do not make swarm chat or internal architecture terminology the primary UX.
2. Where existing contracts support it, show plan/simulation output before authorization, and show the exact authority/approval required for consequential steps. Refusal/blocked states explain the reason and safe next option.
3. Keep UserTrust, AgentTrust, Capability/ProviderTrust and TransactionProof separate. Do not compress them into a single unexplained score.
4. Keep operational truth, observed provider/physical state, and predictive/twin output visibly separate.
5. Autonomous-store controls display objectives, budget/margin/authority boundaries, approval thresholds and stop conditions that are actually represented by the current contracts. Missing controls are marked unavailable rather than simulated as effective policy.
6. Trust/recourse surfaces explain signal → risk → policy outcome → evidence → mitigation/next step. Security BLOCK remains a deterministic hard constraint; defensive outputs do not include weaponized payloads.
7. Preserve UNKNOWN vs FAILED, stale vs fresh, proposed vs committed, and simulated vs executed. An actor/agent trust signal never becomes transaction proof.
8. Synthetic/demo fixtures must be explicitly labelled; no live-provider connection, credential use, order/payment/refund, group-buy commitment or trade-cycle execution.
