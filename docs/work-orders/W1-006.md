# W1-006 — End-to-End Commerce Correctness & Reconciliation Certification

Lane: Worker 1
Status: COMPLETE
Dependencies: W1-005 (merged @ 1e7b01f)

## Objective
Certify the commerce kernel end-to-end: the complete correctness + reconciliation certification that gates the final release candidate. The commerce lane's terminal deliverable — not new features, but proof that the whole kernel (contracts → runtime → twin → projections → transactional surface → autonomous store) is correct as ONE system.

## Scope
Under `packages/commerce` (module-system conforming), building on the fully merged lane (W1-001..005): an end-to-end certification suite that exercises the complete commerce lifecycle as composed journeys — catalog → cart → checkout → payment (auth/capture/settle tri-state) → fulfillment → returns/recourse → reconciliation — each journey replayed through the twin with divergence-checking at every step; cross-aggregate reconciliation certification (order/payment/inventory/till/settlement projections mutually consistent after arbitrary interleavings — property-tested with the fuzz vocabulary spanning ALL stages incl. autonomous-store cycles); money conservation law certified end-to-end (the sum of all money movements is zero across every journey incl. refunds, chargebacks, goodwill, till variance — an explicit invariant test); UNKNOWN-settlement reconciliation certification (every UNKNOWN is either resolved to OBSERVED/FAILED or explicitly expires through the recourse window — no eternal UNKNOWNs, no silent promotion); idempotency certification (every command idempotent under delivery duplication across the full surface); replay certification (checkpoint/resume at EVERY boundary reconstructs identical state — full-journal replay, not just prefixes); twin-equivalence certification at system level (twin ≡ kernel over the union of all fuzz vocabularies, failure + recourse + override + variance interleavings included); a certification report as code — a machine-readable certification result (per-invariant PASS/FAIL with evidence pointers) that the release-candidate gate consumes.

## Truth distinctions
Certification is evidence, not assertion — every claim backed by a named test; money conservation is a hard invariant (zero-sum across all movements); UNKNOWN never silently resolves; the twin is the reference mirror — any divergence fails certification; idempotency + replay are certifiable properties, not best-effort behaviors.

## Acceptance scenarios
1. Full-lifecycle journey: catalog → cart → checkout → pay → fulfill → return → reconcile as one deterministic journey, twin-checked at every step.
2. Money conservation: zero-sum across complete journeys incl. refunds/chargebacks/goodwill/till-variance (property test over the full fuzz vocabulary).
3. Cross-aggregate reconciliation: order/payment/inventory/till/settlement projections mutually consistent after arbitrary interleavings.
4. UNKNOWN settlement lifecycle: every UNKNOWN resolves or expires through the recourse window — never eternal, never silently promoted.
5. Idempotency: every command idempotent under delivery duplication (full-surface property test).
6. Replay certification: checkpoint/resume at every boundary + full-journal replay reconstruct identical state.
7. Certification report: machine-readable per-invariant PASS/FAIL with evidence pointers, consumable by the release gate; ALL PASS.

## Constraints
Certification only — no new commerce features (a gap found is documented + reported, fixed only if mechanical); no cross-lane changes; integer money; all existing suites stay green (cumulative).

## Unlocks
Release candidate (with W2-006 + W3-006 + the feature matrix gate).
