## Objective

The deployment plane's matrix rows are closed at the contract/pointer level (W3-008). The make-it-real program's next step for this plane: a **deterministic deployable-bundle manifest** + a **non-live rehearsal** that proves the bundle assembles and verifies cleanly — the "you could deploy this tomorrow (upon operator authorization)" evidence. This lane builds the definition, the assembly/verification engine, the runner, and the committed artifact. It does NOT deploy anything, does NOT touch any provider, and does NOT read any credential — the standing gates bind (production deployment / live credentials NOT_AUTHORIZED).

## Required behavior (exactly)

1. **The bundle definition** is pure data + types: the inventory contract, the capability declarations (all 11 kinds from `DeploymentCapabilityKind`), the config-surface inventory, the lineage identity. No fs reads at definition time (the runner injects the built output).
2. **The rehearsal** assembles twice and requires identical digests (determinism), verifies every capability kind is declared + its adapter pointer resolves (import-resolvable or symbol-citable per the matrix-audit's pointer discipline), verifies every config key is classified, and records the boot-smoke contract (the declared runtime requirements: edge-api server boot, browser-runtime bundle, etc. — asserted as CONTRACTS, not executed against providers).
3. **The runner** (`node packages/experience/scripts/deployment-rehearsal.mjs`) exits 0 on the current lineage, writes `packages/experience/reports/deployment/deployment-readiness.json` (schema: `generatedAt`, `lineage` {commit}, `bundle` {inventory summary + digest}, `capabilities` [{kind, adapter, replaceable}], `configSurface` [{key, classification, notes}], `verification` [{check, result}], `nonLive` : true with the standing-gates note), and prints an honest summary.
4. **The committed artifact** carries real values from the run (never fabricated); where a value is fixture-derived (e.g. a dist digest placeholder in test contexts), it is labelled.
5. **Honest failure:** any verification failure exits non-zero with the failing check named; never launder a failed check into a pass.
