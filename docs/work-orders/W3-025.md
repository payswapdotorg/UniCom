## Operator authority (2026-10-24, verbatim intent)

"bring back the automations, settings, etc tabs from the original zcode UI as well as the group/project sections. We're building on zcode to use its best features for commerce, not to remove them like you have been doing. We need both zcode UI's best features and Unicom features to be apparent."

The product is ZCode WITH commerce layered in — not ZCode distilled away, and not commerce hiding ZCode. Both worlds must be first-class and apparent.

## Objective

Reverse the W3-024 first-landing demotion: the ordinary root ("/") boots the full ZCode workspace UI — its sidebar with grouped tasks/projects, agents, chat, settings (Automations, Commands, Hooks, MCP, ComputerUse, Browser, OffPeak, plugins) all present as the ordinary first experience — while UNiCOM Commerce stays one prominent, labelled click away and every existing commerce route keeps working unchanged. The desktop app mirrors the same reversal. Both surfaces carry labelled entries to each other; neither is hidden, floating-small, or buried.

- All ZCode workspace surfaces are fully retained in `@zcode/ui` (WorkspaceSidebar, workspace-grouped-tasks, settings sections incl. Automations) — nothing was deleted; only demoted from first landing.

2.
