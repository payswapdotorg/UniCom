1. **Sub-entrypoint:** `packages/experience/src/runtime-browser/index.ts` exporting PURE projection helpers (health-surface projection, telemetry rollup shaping, capability/status taxonomies re-exported as types) + a typed `RuntimeFacts` interface (health snapshots, telemetry counters, capability declarations, journey outcomes — all existing contract types). `package.json` gains `"./runtime-browser": { "types": ..., "default": ... }` matching the package's existing exports-map style.
2. **Browser-clean by construction:** zero `node:` specifiers, zero imports of adapter/vault implementation modules anywhere under `runtime-browser/**`. Enforced by a **module-graph purity test** (static analysis: walk the exports from `./runtime-browser`, assert the graph is clean — pure Node-test, CI-fast, no browser needed).
3. **Parity test:** every fact the browser can render is produced by the same projection code the Node lane uses (single source, two entrypoints). If a projection needs a browser-safe twin, the twin is derived from a shared pure module — never a copy-paste fork; the parity test asserts equivalence on fixture inputs.
4. **No secrets cross the boundary:** browser code receives only serialized facts; the vault's real type stays Node-side; opaque credential refs only (existing contract law).
5. **J15 progressive rendering:** the merchant-connectors module renders live facts when a facts provider is present (the Node/host lane publishes facts — for the lane, a committed, test-pinned facts fixture produced BY the real Node runtime projection is acceptable and must be labelled as such), else the committed SAFE_EXERCISE_RECORD unchanged. The honest boundary text is never removed; live-facts mode ADDS a clearly-labelled live section. Kill switch: absent facts provider → existing record, zero errors.
6. **No live provider connections** — the existing registered-never-connected posture is unchanged (standing gate).
