# W1-002 — Commerce Kernel Core Implementation

Lane: Worker 1
Status: COMPLETE
Dependencies: W1-001 (merged @ 0ff4973)

## Objective
Implement the deterministic Commerce Kernel runtime behind the W1-001 contracts. The contract suite must now run against a real kernel implementation, not contract stubs.

## Scope
Deterministic kernel under `packages/commerce/src/runtime` (or equivalent, module-system conforming): command dispatch with idempotency keys; event-sourced aggregate state (append-only CommerceEvent log + projections); inventory/transfer/receiving state machines; cart/checkout/order lifecycle; weighted/measurement product flows; barcode count observation reconciled into inventory; supplier purchase-order receiving; autonomous-store policy enforcement; returns/exchanges; payment boundary as a typed port (NO provider implementation); subscription/B2B/resale/rental/consignment flows on the kernel; state reconstruction from event replay.

## Truth distinctions
Authoritative operational state, provider/physical observation and predictive estimate remain strictly separated (tri-state). UNKNOWN is never silently promoted. Reconciliation is an explicit, auditable operation.

## Acceptance scenarios
1. All eight W1-001 acceptance scenarios green against the real kernel (no contract stubs on the hot path).
2. Full state reconstruction from event replay yields identical authoritative state (determinism).
3. Duplicate command submission with the same idempotency key produces exactly one consequential effect.
4. Concurrent conflicting commands resolve deterministically (no torn state, revision-checked).
5. Autonomous-store policy limits BLOCK out-of-policy commands at the kernel boundary.
6. Payment boundary port remains provider-agnostic; a test double proves the port contract without any production mock masquerading as a provider.

## Constraints
No floating-point money; immutable IDs/revisions; append-only event log; no provider-specific semantics in the kernel; no model/runtime authority over commerce truth; no production mocks; no scope beyond the commerce lane (agent/UI stay out).
