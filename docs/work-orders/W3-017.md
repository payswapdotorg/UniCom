# W3-017 — J16 Local Camera/QR Capture

**Phase:** Product Completion & Build Readiness, issue #12  
**Owner:** Worker 3  
**Status:** READY_FOR_TL_DISPATCH

## Objective
Resolve the registered J16 camera/QR capture gap with an explicitly user-initiated, browser-local scan path and accessible fallback. It must not silently activate hardware, transmit frames, or create real inventory, order, payment or reservation mutations.

## Required behavior
1. Inspect the existing physical-store flow, supported browsers, installed dependencies and public contract boundary before implementation. Preserve offline queue/replay behavior.
2. Request camera permission only after a clear user action such as **Start scan**. Detect insecure contexts, unsupported APIs and denied permissions without crashing or leaving the camera active.
3. Use browser-native QR/barcode detection when supported. If insufficient, use an existing bundled decoder; if none exists, ask TL to approve a narrowly scoped dependency after reviewing maintenance, bundle size and local-only behavior. Never use remote scripts or remote decoding.
4. Keep camera frames and images in memory only. Do not upload, persist, log or emit them in telemetry. Do not request permissions on page load. Stop media tracks after scan, cancel, navigation/unmount or failure.
5. Provide accessible manual code entry as a reliable fallback. A local image-file fallback may also be provided. Display unsupported/denied states and support retry/cancel.
6. Decode only into the existing demo/local inventory workflow. Preserve DEMO/simulated labels where inventory truth is not connected. A successful decode is not provider-verified stock, consent or a commitment.
7. Test permission grant/denial, unsupported API, malformed/unknown code, successful local decode, cancel/track cleanup, repeated scans, manual fallback and absence of image-network transmission. Use a deterministic camera/decoder seam for CI; real-browser interaction remains mandatory.

## Acceptance
- [ ] Camera starts only after explicit user action; all exit paths stop tracks.
- [ ] Supported QR scan or bundled local-image decode produces an observable local result.
- [ ] Manual entry is accessible and works when camera APIs are absent or denied.
- [ ] Frames/images are not transmitted, persisted or logged; enforce via network tripwire and tests.
- [ ] No provider calls or commerce-plane mutations occur.
- [ ] J16 browser evidence covers success and a denial/fallback path on the merged tree.
- [ ] Existing offline queue/replay and journey regressions pass; manifest validation and denominators are sound.

## Forbidden
Silent camera activation; remote image decoding; media uploads; frames in telemetry; treating a scanned code as authorization, verified stock or consent; live inventory/order/payment changes; dependency-law violations.
