# W1-001 — Commerce Domain Contracts

Lane: Worker 1
Status: COMPLETE
Dependencies: none

## Objective
Define deterministic Commerce Kernel contracts without implementing agent optimization.

## Scope
Canonical contracts for merchant/customer/principal, Product/Variant/SKU/Catalog/Collection, Price/Promotion, Inventory/Location/Transfer/Receiving, Cart/Checkout/Order, Payment boundary, Fulfillment/Shipment, Return/Exchange, Subscription, B2B, resale/rental/consignment, CommerceEvent, Opportunity references, AutonomousStorePolicy, and weighted/measurement products.

## Truth distinctions
Represent authoritative operational state, provider/physical observation and predictive estimate separately. Never silently promote one to another.

## Acceptance scenarios
1. Online product/order/inventory lifecycle.
2. Multi-location transfer.
3. Weighted grocery item.
4. Barcode-based count observation reconciled into inventory.
5. Supplier purchase-order receiving.
6. No-RFID supermarket inventory flow.
7. Autonomous-store policy limits.
8. Idempotent command/state transitions.

## Constraints
No floating-point money; immutable IDs/revisions; idempotency for consequential commands; UNKNOWN for ambiguous external observations; no provider-specific semantics in domain contracts; no model/runtime authority over commerce truth.

## Unlocks
W1-002.
