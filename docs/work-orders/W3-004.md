# W3-004 — Physical Commerce Edge + Live-Commerce UX

Lane: Worker 3
Status: READY
Dependencies: W3-003 (merged @ c2701d2)

## Objective
Deliver the physical-commerce edge: supermarket-grade store operations WITHOUT RFID — POS/import, barcode + mobile count, weighted products, offline observation queue, reconciliation — and the live-commerce UX surface, all riding the W3-003 connector execution runtime and LocalCommerceEdge.

## Scope
Under `packages/experience` (module-system conforming), on top of the W3-003 connector runtime + LocalCommerceEdge + browser-only session isolation: the POS/import connector path — catalog + inventory import from POS/back-office sources through the canonical connector execution modes (PASS_THROUGH_NATIVE / COMPOSED / OPTIMIZED_MULTI_PROVIDER) with idempotent ingestion and backoff; barcode + mobile count workflows — count observations captured via edge devices (browser-only connectors), journaled through LocalCommerceEdge exactly-once, folding into the commerce seam's inventory facts; weighted-product workflow — weight-captured items (price-per-unit × observed weight, integer minor units, tolerance bands for variance) from edge capture through commerce facts; offline observation queue — edge observations accumulated while disconnected, time-stamped + sequence-stamped at capture, replayed through LocalCommerceEdge with exactly-once semantics and explicit conflict/supersede rules (a stale offline observation never silently overwrites a fresher online fact); reconciliation journeys — edge counts vs system counts vs POS deltas with tri-state preservation (UNKNOWN stays UNKNOWN); live-commerce UX — the buyer-facing live-commerce session surface (arrival-ordered event stream per W3-003's live-commerce connector, backpressure-respecting render contract as a typed schema/consumer contract — no bespoke UI framework, the contract is the deliverable) including live session lifecycle (announce → active → ended), replay-from-start for late joiners, and W2-lane trust signals consumed as OPAQUE branded references; supermarket journey demonstrations WITHOUT RFID: POS/import path, barcode/mobile count, LocalCommerceEdge, weighted-product workflow, offline observation queue, reconciliation — each as an executable journey test, not a document. RFID remains optional and out of scope.

## Truth distinctions
The edge is an observation surface, never a source of truth — observations are evidence that fold into commerce facts through the connector contract; offline observations carry capture-time truth (sequence + timestamp) and are superseded only by the journaled conflict rules; weighted-product pricing is exact integer math with explicit tolerance, never floating point; live-commerce UX contracts are typed schemas — the consumer contract is the deliverable, rendering is downstream.

## Acceptance scenarios
1. POS/import journey: a POS catalog+inventory import flows through a fixture-backed connector in each execution mode with idempotent re-import (double import = zero duplicate facts).
2. Barcode/mobile count journey: edge count observations (browser-only connector) journal through LocalCommerceEdge exactly-once; the count folds into the commerce seam's inventory facts as the correct tri-state value.
3. Weighted-product journey: weight capture (including variance within tolerance, and variance outside tolerance → explicit rejection/UNKNOWN) prices to exact integer minor units; no floating-point money anywhere in the path.
4. Offline queue journey: observations captured offline (sequence + timestamp at capture) replay exactly-once after reconnect; a stale offline observation conflicting with a fresher online fact follows the journaled supersede rule — never a silent overwrite (asserted).
5. Reconciliation journey: edge counts vs system vs POS deltas reconcile with UNKNOWN preservation; a variance is an explicit journaled state.
6. Live-commerce session journey: announce → active → ended lifecycle with arrival-ordered event delivery; a late joiner replays from start through the same typed contract; backpressure (slow consumer) does not reorder or drop silently.
7. Trust signal consumption: W2-lane trust signals surface in the live-commerce UX contract as OPAQUE branded references (no trust semantics implemented in this lane).
8. Execution-mode gates: each new connector path enforces the W3-003 mode-permission matrix and capability-scope gates (a connector operating outside its granted mode/scope is rejected — asserted).

## Constraints
No commerce-state ownership (Worker 1 lane — commerce facts only through the opaque seam); no trust/proof semantics (Worker 2 lane — opaque references only); no RFID dependence; no floating-point money; no provider integrations beyond fixture-backed adapters (real credentials stay out); no production mocks of the commerce kernel; no scope beyond the experience lane.
