# W3-001 — Experience, Connector, Physical Edge and Deployment Boundaries

Lane: Worker 3
Status: READY
Dependencies: none

## Objective

Freeze the public experience and integration boundaries so the product can operate across API, browser, live-commerce and physical channels without leaking provider-specific semantics into domain code.

## Scope

Define interfaces for:
- Merchant Command Center;
- Buyer Intent Canvas;
- Opportunity Inbox;
- Decision Card;
- Connector Studio;
- trust/security surfaces;
- storefront integration;
- Connector transport;
- isolated BrowserSession capability;
- live-commerce stream;
- physical commerce observation;
- POS/barcode/QR/NFC/RFID boundary;
- webhook/event ingestion;
- deployment provider abstractions;
- realtime task/live-event channel.

## Connector requirements

Must support:
- API/SDK;
- REST/GraphQL;
- MCP/UCP/ACP/A2A adapters;
- CLI;
- file/feed/EDI/SFTP/email;
- browser;
- live-commerce;
- physical edge.

Do not define a second capability vocabulary. Consume W2-001 canonical semantics.

## UI requirements

The primary surfaces are:
- Command Center / Work Graph for merchants;
- Intent Canvas for buyers.

Conventional admin pages remain secondary.

## Acceptance

- UI contracts documented;
- real responsive prototypes/fixtures;
- browser E2E harness boundaries;
- connector session-security contract;
- provider-state display contract;
- deployment adapter contract;
- no domain package depends on Vercel/Cloudflare/Neon/etc.
