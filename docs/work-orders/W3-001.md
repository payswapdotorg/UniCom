# W3-001 — Experience, Connector, Physical Edge and Deployment Boundaries

Lane: Worker 3
Status: READY
Dependencies: none

## Objective
Freeze public experience and integration boundaries so every capability is discoverable and external systems can be connected even without API/MCP/CLI.

## Scope
Define interfaces for Merchant Command Center, Buyer Intent Canvas, Opportunity Inbox, Decision Card, Connector Studio, Trust/Security, storefront, connector transports, isolated BrowserSession, live-commerce stream, LocalCommerceEdge, physical commerce observation, POS/barcode/QR/NFC/RFID boundary, webhook/event ingestion, deployment provider adapters and realtime task/live-event channels.

## UX acceptance
Every feature in docs/FEATURE-COMPLETENESS-MATRIX.md has a primary or contextual discovery path plus visible state/explanation, action and history/evidence where consequential.

The UI visibly exposes group-buy, trade/swap opportunities, resale/rental, autonomous store, Commerce Twin, security, connector health, LocalCommerceEdge and live commerce.

## Connector acceptance
Support API/SDK, REST/GraphQL, MCP/UCP/ACP/A2A adapters, CLI, file/feed/EDI/SFTP/email, browser, live commerce and physical edge.

LocalCommerceEdge supports authorized browser, shared-file, USB, serial and LAN interfaces and offline observation queuing.

Do not create a second capability vocabulary; consume Worker 2 semantics.

## Deployment acceptance
No domain package depends directly on Vercel/Cloudflare/Neon/Upstash/Apify.
