## The seven laws to specify (from decision §2, binding)

1. **Formation/execution truth is separate from downstream commitments** — a formed GroupBuy is not an order; an executed leg is not a payment. Spec: forming a GroupBuy / executing a leg (current commands) produces NO order, payment, reservation or recourse object in kernel state.
2. **Per-side-effect authorization** — each downstream object requires its own actor-authorized command with its own consent basis. Spec: a GroupBuy participant's join consent does not authorize an order placement on their behalf; a leg execution consent does not authorize inventory reservation.
3. **Idempotency** — every command with an idempotency key retried returns the ORIGINAL receipt and never duplicates an effect (the existing DUPLICATE law). Spec: duplicate order placement / payment intent commands return the original receipt.
4. **Actor authority** — who may create a downstream object derives from the aggregate's own actor laws. Spec: a non-organizer cannot place the order the organizer's surface would propose; a non-consenting participant cannot; nobody else can.
5. **Cancellation/compensation separation** — compensation (refund/unreserve) is its own separately-authorized command, never automatic. Spec: cancelling/refusing upstream never auto-refunds or auto-unreserves; refund requires its own authorized command.
6. **UNKNOWN is not FAILED** — a pending downstream result surfaces UNKNOWN, never a failure. Spec: the existing UNKNOWN states (e.g. payment intent pending) are preserved as UNKNOWN through retries/timeouts.
7. **Refusal must not commit other legs** — refusing one leg/one participant never commits others. Spec: leg refusal + other legs' execution states remain exactly as the aggregate law defines.
