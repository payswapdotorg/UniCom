# W3-002 — Connector Runtime + Browser/Session Isolation

Lane: Worker 3
Status: COMPLETE
Dependencies: W3-001 (merged @ 9cfd466); consumes W2-001 capability vocabulary (merged)

## Objective
Implement the connector runtime framework and browser session isolation behind the W3-001 boundary contracts.

## Scope
Connector runtime under `packages/experience` (module-system conforming): adapter lifecycle (register/connect/observe/disconnect); connector health observation and reporting; execution-mode dispatch plumbing for PASS_THROUGH_NATIVE / COMPOSED / OPTIMIZED_MULTI_PROVIDER (real provider adapters come in W3-003 — this order delivers the dispatch framework, not specific providers); browser session runtime with per-session isolation (separate identity, storage and authority boundaries); untrusted-content sanitization at every render/ingest boundary; offline observation queue with explicit no-promotion semantics (observations stay observations until reconciled by the commerce lane); credential vaulting at the connector boundary — credentials never enter model context; transport-coverage plumbing for API/SDK, REST/GraphQL, MCP/UCP/ACP/A2A, CLI, file/feed/EDI/SFTP/email, browser, live commerce and physical edge (transport abstractions; live adapters later).

## Truth distinctions
Connector observations are never promoted to authoritative state by the experience plane. UNKNOWN ≠ FAILED. Offline queue contents are observations, not truth.

## Vocabulary discipline
Consume Worker 2's canonical capability vocabulary via the typed seam now available post-W2-001 merge (`@unicom/agent` public entrypoints). Do NOT create a second capability vocabulary. If the seam needs widening, stop and report the gap instead of duplicating.

## Acceptance scenarios
1. All nine W3-001 areas green against the real runtime (no contract stubs on the hot path).
2. Two concurrent browser sessions cannot read each other's storage, identity or authority (isolation test).
3. Untrusted content (malicious markup/script-bearing ingest) is neutralized at the boundary (adversarial test).
4. Offline queue drains to the commerce lane as observations with no silent promotion; reconciliation is explicit.
5. A credential entering the connector runtime is vaulted and provably absent from any model-context boundary (adversarial test).
6. Execution-mode dispatch routes a journey through each mode's plumbing with provider-agnostic stubs clearly marked as test doubles (no production mocks).
7. No domain package depends directly on Vercel/Cloudflare/Neon/Upstash/Apify (deployment guard test stays green).

## Constraints
No second capability vocabulary; no canonical commerce truth; no UI implementation beyond what the runtime contracts require (full UX comes later); no production mocks; no provider adapters in this order (W3-003).
