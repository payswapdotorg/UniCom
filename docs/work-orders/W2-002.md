# W2-002 — ZCode Agent Kernel Adaptation

Lane: Worker 2
Status: READY
Dependencies: W2-001 (merged @ e35abbc)

## Objective
Adapt the existing ZCode agent kernel (the repo's agent runtime packages) to realize the W2-001 agent-plane contracts: MainAgent as the single principal identity, skills as default specialization, and ephemeral delegates with attenuated authority.

## Scope
Wire `packages/agent` contracts into the ZCode agent kernel runtime: MainAgent principal identity and session ownership; skill registry + default specialization routing; ephemeral delegate spawning with scoped, attenuated authority (time-bounded, capability-bounded, revocable); the canonical capability vocabulary as the single source of executable capability semantics (typed executability preconditions enforced by the kernel, not the model); context/memory policy boundaries — credentials, cookies, MFA codes and browser storage NEVER enter model context; System 1 / JEPA / System 2 routing hooks with deterministic selection policy; security immune-system enforcement point (BLOCK is final; defensive-only signatures; no model override); strategy/organization separation preserved at runtime.

## Truth distinctions
The commerce seam stays opaque and idempotent (capability references only). The agent plane never becomes canonical commerce truth. Trust is not proof; proof selection (P0–P5) remains explicit.

## Acceptance scenarios
1. All eleven W2-001 acceptance scenarios green against the adapted kernel (real runtime paths, not contract stubs).
2. A delegate exceeding its attenuated scope is refused by the kernel (defense-in-depth test — model prompt cannot widen authority).
3. Executable-capability attempt without a connected instance + observation is refused with the typed precondition failure.
4. A credential-shaped secret in any kernel-mediated context is redacted/blocked before reaching a model-context boundary (adversarial test).
5. Security BLOCK survives a model attempt to override (final, deterministic).
6. GroupBuy and TradeCycle commitments remain explicit; no silent enrollment or silent cycle extension at runtime.

## Constraints
No canonical commerce state; no provider-specific connector implementations; no UI implementation beyond schema needs; no browser credential/session handling (W3 lane); delegates remain ephemeral and bounded; no production mocks.
