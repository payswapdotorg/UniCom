## Objective

The phase-IV rehearsal proved the bundle assembles + verifies deterministically from the SOURCE tree — but the artifact a real deployment would consume is the canonical DIST (the Vite build output), and the BUILD gate proved that dist deterministic ON CI (whole-output digest sha256 5f5e5248… on lineage 29c7ae7, hidden sourcemaps, memory floor 10.3+ GB — a class the sandbox cannot run: 13 documented OOM kills). This lane closes the gap WITHOUT breaking any banked law: the dist is never uploaded or committed by CI (the BUILD-ONLY law); instead the rehearsal consumes CI's OWN small-text evidence (the `dist-manifest-sha256.txt` per-file manifest + the `DIST_DETERMINISTIC_SHA256` line in `evidence-summary.txt`) and verifies the dist contract against it — classification, completeness, determinism, and the source↔dist cross-check — recording the end-to-end hash chain in the artifact. The result: "the deployed artifact is hash-verified end-to-end" becomes a machine-checked statement, and any future authorized deployment lane inherits the verification for free.

## Required behavior (exactly)

1. **The dist contract is pure data + types** (the bundle-definition extension): the file classes, the manifest line format, the digest rule, the hash-chain identity. No fs reads at definition time.
2. **The manifest assembly** accepts the canonical build's evidence format verbatim (`<sha256hex>  ./<relative-path>` lines, sorted by path — exactly what `find . -type f -exec sha256sum {} \; | sort -k2` emits): every line parses, every file classifies, unclassifiable files fail the completeness check honestly (named, exit non-zero in the strict modes).
3. **Determinism**: two independent assemblies from the same manifest input produce the IDENTICAL dist digest (the same two-assembly discipline as the source inventory).
4. **The source↔dist cross-check**: every entrypoint-class source inventory entry maps to ≥1 dist artifact class (the mapping declared in the contract); the cross-check result is recorded per entrypoint class.
5. **The modes are honest**: `--dist-manifest` (CI evidence) → `mode: "ci-evidence-manifest"` with the digest + file count recomputed from the manifest; `--dist-root` → `mode: "dist-root"` walking the real dir; neither → `mode: "source-only"` with the honest reason. The committed artifact never fabricates a dist value; fixture-derived values carry the `committed-fixture` provenance label.
6. **The existing behavior is preserved unchanged**: the source-tree inventory, the capability verification, the config-surface classification, and the 8 existing checks keep their current contracts (the artifact's existing sections stay schema-compatible — additive fields only).
7. **Honest failure**: any dist-verification failure exits non-zero with the failing check named; never launder.
