# W3-005 — Merchant/Buyer/Connector/Autonomous UX Hardening

Lane: Worker 3
Status: READY
Dependencies: W3-004 (merged @ 2df3c88)

## Objective
Harden every operational surface to the UX completeness contract: every feature discoverable through primary navigation, universal intent, contextual opportunity, or onboarding/empty states; Decision Cards communicating their full contract; connector + autonomous-store + live-commerce state visible and actionable; empty/loading/error/offline states handled on every surface. Hidden feature = incomplete feature.

## Scope
Under `packages/experience` (module-system conforming), on top of the merged W3-002 connector runtime + W3-003 connector execution/adapters + W3-004 physical edge/live-commerce UX: navigation completeness — every surface (Command Center, Intent Canvas, Opportunity Inbox, storefront, catalog/orders/inventory/customers operational surfaces, connector studio, Trust/Security, Explore/Capabilities, Settings, live-commerce) reachable through typed navigation with zero orphan routes; a universal-intent surface — every feature addressable through a typed intent/command path (typed contracts, no freeform strings); contextual-opportunity + onboarding/empty states on every surface (empty states propose the first action; loading + error states typed + rendered); Decision Card hardening to the full contract: objective, state, evidence, alternatives, predictions, downside/risk, organization/capabilities used, authority/approval, action — every field present + typed + renderable, opaque references to W2 vocabulary verbatim; connector health — per-connector status, last-contact, error, recovery surfaces fed by the W3-003 execution-mode journeys; autonomous-store visibility — the merchant sees autonomous store state, running policies, variances, escalations, and override points (opaque commerce references, no commerce semantics invented); live-commerce UX completeness — lifecycle (announce → active → ended) visible, late-joiner replay-from-start, backpressure-respecting consumer states surfaced; offline degradation — W3-004's offline observation queue surfaces sync state + journaled supersede outcomes in the UX.

## Truth distinctions
Every feature has at least one discoverable user path (typed-test-proven, not doc-claimed); the UI never invents commerce/agent semantics — opaque references only; all state surfaces are typed contracts; offline is a first-class rendered state, never a silent failure; capability vocabulary is consumed from Worker 2 verbatim, never duplicated.

## Acceptance scenarios
1. Navigation completeness: typed contract test — every registered surface reachable, zero orphans, primary nav + universal intent both resolve.
2. Decision Card contract: every card renders the full 9-field contract (objective, state, evidence, alternatives, predictions, downside/risk, organization/capabilities, authority/approval, action) — typed + asserted.
3. Connector health: per-connector status/last-contact/error/recovery surfaces exist + populated by execution-mode journey states (typed tests over the W3-003 seams).
4. Autonomous-store visibility: store state, running policies, variances, escalations, override points all surfaced (opaque commerce references rendered verbatim).
5. Empty/loading/error/offline: every surface implements all four states; offline surfaces the observation-queue sync + supersede state (typed tests).
6. Live-commerce UX: lifecycle visible; late-joiner replay-from-start works; backpressure consumer states render; ended sessions show terminal state.
7. Onboarding/empty states: every empty state proposes the next action (typed assertion on the empty-state contract).

## Constraints
Consume Worker 2's canonical capability vocabulary (opaque references only — never a second capability model); commerce state read-only via contracts (no commerce semantics in the UI layer); no model/trust policy decisions (Worker 2 lane); no commerce-kernel changes (Worker 1 lane); no production mocks (test doubles clearly marked); no scope beyond the experience lane.
