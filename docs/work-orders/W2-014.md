## Objective

Close the recorded J12 gap: additional B2B experience-contract surfaces remain contract-only and/or demo-labelled without complete rendered interactive coverage. Make the intended user-facing B2B flows visible, accessible and honestly labelled while remaining inside architecture baseline `1.1-frozen-2026-10-05`.

## Required steps

1. Read `docs/rendered-ui/FINAL-REPORT.md`, `docs/runtime-integration/FINAL-REPORT.md`, prior W2/W3 work orders and the public commerce/experience contracts. Identify each J12 element that is still contract-only, absent or merely a non-interactive illustration. Do not infer functionality from types alone.
2. Create a small contract-to-UI map: current contract, rendered consumer, role/permission, state provenance (kernel/runtime/fixture), available interactions and explicit remaining limitations.
3. Complete the narrowest useful set of rendered B2B interactions supported by the existing contracts and frozen dependency graph. Preserve role-aware denial, keyboard/screen-reader accessibility, useful empty/loading/error/UNKNOWN states, and deterministic resettable synthetic fixtures.
4. Mark every synthetic or disconnected path as DEMO/simulated. Do not represent a UI acceptance, approval or fixture mutation as an actual purchase order, payment, reservation, shipment, provider connection or commitment.
5. Add lane-local unit/interaction tests and real Chromium/Playwright evidence for all newly completed J12 controls, including an allowed and a denied role, validation/error handling, and state reset.
6. Document functionality still blocked by the separately gated commerce-plane linking decision; do not create a substitute local commitment.
