# W2-009 — Professional Personas, Incumbent Baselines and Adoption Measurement

Lane: Worker 2 — Agent / Trust / Lab / Security
Status: READY
Dependencies: V3 simulation charter + W1-009 and W3-009 interface contracts (contracts reviewed in parallel)

## Objective
Define fair and reproducible synthetic professional agents and incumbent-comparison criteria, then estimate simulated full-switch and main-interface willingness without presenting synthetic outputs as actual market research.

## Scope
- Create 15,275 seeded persona records across the 39 firms and declared staff sizes.
- Include procurement, project/program management, field/operations, finance/accounting, sales, IT, compliance/audit, approver/executive and other industry-specific roles.
- Give personas different tool familiarity, role permissions, cost/risk sensitivity, switching costs, training availability, compliance sensitivity, trust thresholds and preferred workflow.
- Map each persona to 200-project portfolio exposure and the specific user journeys they need to complete.
- Select representative incumbent stacks by firm size and industry from the approved matrix; freeze edition/access/evidence class.
- Produce benchmark task equivalence and outcome scoring. Do not claim market-share rankings from vendor homepages.
- Define evidence classes: A actual authorized GUI trial; B official interactive demo/UI; C official documentation checklist.
- Freeze score weights, technical eligibility rules, full-switch threshold, main-interface threshold and sensitivity analysis before baseline.
- Evaluate the seven-way organization/model configurations already present in the Reality/Learning Lab where decision quality is relevant, but don't confound model evaluation with GUI adoption.
- Produce reason-coded choice explanations: capability gap, UI friction, trust/compliance, price/cost, integration readiness, training/switching cost, or preference.
- Protect simulated professional autonomy: a synthetic persona may reject UNiCOM; never tune all personas to prefer it.

## Acceptance criteria
1. Exactly 13 industries, three firm sizes and 39 firms.
2. Exactly 15,275 distinct synthetic professional personas using declared population assumptions.
3. The incumbent stack is selected per cohort and evidence class is explicit.
4. Every comparison uses equivalent tasks/inputs/outcomes; no modeled competitor runtime is mislabeled as observed.
5. Define separate outputs for (a) technical full-switch eligibility, (b) simulated willingness to switch completely, (c) main-interface eligibility and (d) simulated willingness to use as main interface.
6. Report both numerator and denominator by industry/firm-size/role plus cohort-seed sensitivity.
7. Critical failures veto adoption regardless of weighted score.
8. Score formulas are versioned and frozen before baseline; any change requires rescore and TL sign-off.
9. Output a report schema plus test fixtures that prove scores change in the correct direction for blockers, friction and improvements.
10. Explicitly label that simulated willingness is not human survey intent and requires later validation with consenting real professionals.

## Constraints
No chain-of-thought capture. Use concise evidence/rationale fields only. No real personal, patient, financial-account, privileged legal or classified data.

## Definition of complete
A versioned adoption measurement contract and reproducible synthetic cohort exists, with unit/property tests and a benchmark mapping that the integrated GUI experiment consumes.
## Scope clarification — commerce-only incumbent benchmark

Do not select broad vertical applications as overall competitors. For every synthetic firm, select incumbent products/workflows only for the commerce capabilities UNiCOM provides or intends to provide: purchasing/procurement, supplier marketplaces/portals, storefront/catalog/checkout, POS/inventory, B2B, group buying, rental/resale, trade, opportunity discovery, fulfilment/returns and connected commerce capabilities. General industry software is out of scope unless a specific commerce capability can be isolated and tested.

Use the revised docs/simulations/V3-INDUSTRY-AND-COMPETITOR-MATRIX.md as the only industry comparison matrix. Do not claim a tool is the most popular absent credible evidence. Label all competitor data A/B/C/D, with D excluded from performance/superiority claims.

The experiment's journey coverage must separately measure the full-switch and main-interface impact of:
- buyer intent, buy/wait, quote comparison, negotiation and substitution;
- existing and merchant-proposed GroupBuy, recruitment and explicit commitments;
- rent/borrow vs buy;
- proactive resale/rental/consignment and other economic opportunities;
- bounded, individually authorized multi-hop TradeCycle;
- merchant commerce lifecycle and supplier/procurement workflows;
- autonomous-store controls and Commerce Twin scenarios;
- physical/no-RFID retail;
- trust/security, fraud disputes, connector failures, UNKNOWN and recourse.

A single global adoption average may not mask an industry/role where one of these applicable journeys is undiscoverable or unsafe.
