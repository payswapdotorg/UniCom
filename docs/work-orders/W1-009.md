# W1-009 — Industry Project, Procurement and Outcome Scenario Portfolio

Lane: Worker 1 — Commerce Truth / Economic Execution
Status: READY
Dependencies: V3 simulation charter + existing commerce contracts

## Objective
Provide deterministic, realistic synthetic project and purchasing scenarios for the 13 industries in docs/simulations/V3-INDUSTRY-AND-COMPETITOR-MATRIX.md, retaining UNiCOM's deterministic commerce truth and authority boundaries.

## Scope
- Define project templates and task outcomes for 13 industries × small/medium/large synthetic firms.
- Generate 200 project instances per firm using reproducible seeds, stable ids and distinct baseline/holdout seed namespaces.
- Include project dependencies, purchasing lists, quantities, budgets, deadlines, supplier quote changes, quality thresholds, approvals, substitutions, delivery modes, returns/recourse and required evidence.
- Include small/medium/large workload and concurrency variations.
- Include weighted grocery/no-RFID journeys and manufacturing/contractor project supply chains.
- Define assertions for cost validity, budget constraints, deadline feasibility, stock reconciliation, idempotency, provider UNKNOWN and approval policy.
- Create machine-readable task fixtures, scenario manifest and outcome oracle; synthetic truth only.
- Keep canonical commerce state deterministic. Twin/prediction remains non-authoritative.
- Ensure projects test the product's declared scope and explicitly distinguish out-of-scope regulated functions.

## Acceptance criteria
1. 39 firm cohorts are represented.
2. Each firm manifest declares 200 project ids (7,800 total) and deterministic seed.
3. Role mix matches firm size and industry; at least 8 role families per industry (e.g. project owner, procurement, finance, ops, end user, approver, supplier, auditor/security).
4. Project purchasing scenarios cover supplier comparison, budget/deadline/quality conflict, approvals, substitution, partial availability, delivery, return/recourse and evidence.
5. No-RFID supermarket coverage passes the W3-004 contracts and docs/SUPERMARKET-WITHOUT-RFID.md.
6. Expected outcomes and critical failure conditions are machine-readable and non-vacuous.
7. No scenario changes real production state or calls a live payment rail.
8. Contract and regression tests prove deterministic reproduction, idempotency and UNKNOWN preservation.
9. Fixtures are explicitly separated from GUI journey execution; they cannot mark a user journey successful.
10. Deliver an integration report with file pointers, counts, seeds and tests actually run.

## Non-goals
No change to frozen Commerce Kernel semantics, no floating-point money, no provider-specific domain truth, no production-like fake balances, no direct model authority and no construction of a hidden non-UI task execution path.

## Definition of complete
The scenario portfolio exists, is deterministic, covers all 7,800 project manifests, and its assertions are exercised by the GUI-runner work order before the TL accepts the baseline.
