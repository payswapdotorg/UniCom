## Scope
Under `packages/experience` (module-system conforming), building on the fully merged lane (W3-001..005 incl. the hardened UX completeness contract): deployment adapters as code — provider-agnostic deployment manifests + configuration surface (environment contracts, build steps, health/readiness probes, startup ordering) with at least one fully-specified target adapter (e.g. Node/server or container) runnable end-to-end in CI/tests; browser E2E over the hardened surfaces — typed E2E journey suites exercising the primary user paths (Command Center, Intent Canvas, Opportunity Inbox, storefront → checkout journey, connector studio, Trust/Security, live-commerce session incl. late-joiner replay) against the real UI contract, runnable headless in the test battery; production observability — typed health/status contracts (per-subsystem health, connector health, autonomous-store state, live-session state), structured event/telemetry surface wired to the existing journaled event streams (no new truth — projections of journal state), operator dashboard surfaces for the same; the disaster/recovery runbook as code + tests — backup/restore contracts (journal export/import, projection rebuild from journal replay, configuration state restore), failure-mode playbooks (connector outage, pod loss, journal corruption detection via hash-chain verification, split-brain avoidance through the single-writer kernel law), recovery-time objectives expressed as testable contracts (rebuild-from-journal verified in tests); release-candidate evidence: E2E results + observability contracts + DR drill results as machine-readable reports consumable by the release gate.

## Truth distinctions
Readiness is proven, not claimed — every runbook step is a tested contract, not documentation prose; E2E runs against real UI contracts (no mocked-away surfaces); observability projects existing journal truth (never a second source of truth); recovery = rebuild from the journal (the journal is the sole authority — projections are disposable); every deployment surface is typed + tested.

## Acceptance scenarios
1. Deployment adapter: a fully-specified target adapter builds + boots + passes health/readiness probes end-to-end in a test (headless).
2. Browser E2E: the primary-path journey suite (incl. storefront → checkout + live-commerce late-joiner replay) runs green against the real UI contract.
3. Observability contracts: per-subsystem health + connector health + autonomous-store + live-session status all exposed as typed contracts, wired to journal-derived projections (tested).
4. Backup/restore: journal export → import → projection rebuild reproduces identical state (tested round-trip).
5. Failure modes: connector outage + pod loss + journal-corruption detection each have a tested playbook path (detection → journaled decision → recovery action).
6. Rebuild-from-journal: full projection rebuild from journal replay verified (recovery contract, tested).
7. RC evidence: E2E + observability + DR drill results as machine-readable reports; ALL PASS.
